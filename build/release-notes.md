# SuperMask 超级面具 v1.1.2

> **必须更新**：v1.1.0 / v1.1.1 的 exe 存在打包缺陷，双击后只弹错误框"无法将参数绑定到参数Path / param无法识别"，**主界面无法出现**。本版已修复并实测主界面正常。

给 Windows 浏览器戴上"地理位置面具"：**GPS 坐标 / 时区 / 语言 / WebRTC** 一键伪装，**自动同步 VPN 出口**，**运行时注入、不改系统文件、关闭即恢复**。

## v1.1.2 更新内容

### 🐛 修复：exe 双击后无法启动主界面（重要）

问题出在打包环节（PS2EXE 单文件合并），共两层缺陷，均已在本地实测修复：
1. 合并脚本中残留 `$PSScriptRoot` 引用 —— exe 模式下它为空字符串，启动即报"无法将参数绑定到参数Path"；
2. `param()` 块被 lib 代码压在中间 —— PowerShell 要求 param 必须是脚本第一条语句，报"param 无法识别"。

现在双击 `SuperMask.exe` 会直接出现主界面。**v1.1.1 的 WebRTC 泄漏修复全部包含在本版中。**

### 关于"Public IP Address 还是 120.235.237.130"

先说结论：**面具本身永远不会改变 Public IP** —— 公网 IP 由你的 VPN/代理决定，面具负责的是让 GPS/时区/语言/WebRTC 与出口完全一致。

在面具浏览器里实测（v1.1.2）：页面真实公网 IP = `38.106.19.252`（洛杉矶 VPN 出口），不是 120.235.237.130。

如果你看到 Public IP 显示 120.235.237.130（广州），说明**你查看的那个浏览器流量没有走 VPN**，常见原因：
- 面具浏览器已经退出/没在运行（可看面具主界面状态栏是否"运行中"）
- VPN 没开、断开了，或系统代理没开（面具启动前请先启动 VPN）
- 在日常浏览器里查看（Firefox 默认不走系统代理；或 VPN 客户端对该进程不生效）

排查顺序：**先开 VPN → 打开面具 → 点「启动面具」→ 在弹出的面具浏览器里访问 browserleaks → 点「验证伪装」看四项结果**（内置 WebRTC 泄漏探测会实测公网映射 IP 并与出口比对）。

## v1.1.1 更新内容（本版包含）

- **修复 WebRTC 真实 IP 泄漏**：Chrome 在 HTTP 代理下会绕过 UDP 策略直连 STUN；现改为 JS 层禁用 RTCPeerConnection（确定性拦截）+ 面具浏览器显式代理 + 原策略兜底
- **新增 WebRTC 泄漏检测**：「验证伪装」用多路 STUN 实测公网映射 IP 并与出口比对
- **自动同步 VPN 出口**：读取系统代理探测出口 IP，坐标/时区/语言全自动一致

## 使用方法

1. **先启动 VPN/代理**，再运行 `SuperMask.exe`（zip 请先解压再运行）
2. 地点保持「自动 · 同步VPN/代理出口(推荐)」
3. 点 **▶ 启动面具** → 在弹出的独立面具浏览器里正常上网
4. 点 **✓ 验证伪装** 确认四项全 [OK]
5. 用完点 **■ 停止并恢复**，或直接关闭面具浏览器窗口

如果杀毒软件拦截/删除 exe：右键文件 → 属性 → 勾选"解除锁定"；或将 exe 加入杀软白名单；或下载 Release 里的 Source code（zip）解压后双击 `StartSuperMask.bat`（源码方式，无需 exe）。
